# 历史记录：v1.1（已被 v1.2 取代）

> 本文仅保留用于说明旧问题。实际运行规则以 `V1.2-DATA-CLEANUP.md` 为准。


问题：v13 每次启动都会把 backups/*.json 当作“历史来源”重新合并。删除操作本身会先生成删除前备份，所以被删除的笔记会在下次启动时再次出现，并可能因为同 ID 不同内容而生成“（恢复副本）”。

修复原则：

1. 可读取的持久化 data/notes.json 永远是当前真相，包括空数组。
2. 正常启动不扫描、不合并 backups。
3. 只有 data/notes.json 缺失或损坏时才执行恢复。
4. backups 是完整数据库快照；恢复时只取最新有效快照，不逐份合并。
5. 不自动清除已经产生的恢复副本，避免误删独有内容。

这样删除、编辑和清空笔记的结果都会稳定保存在主数据库中，同时保留真正发生文件丢失/损坏时的恢复能力。
