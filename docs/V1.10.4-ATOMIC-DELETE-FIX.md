# v1.10.4 Atomic delete fix

- Root cause reproduced in Chromium: selecting an editable excerpt parent that contains a `contenteditable=false` source and running native delete can leave an empty excerpt shell; making only the parent non-editable still lets native delete merge adjacent blocks.
- The whole excerpt/capture is now `contenteditable=false`.
- Atomic deletion no longer calls native `execCommand("delete")`; it removes exactly the top-level capture node and keeps adjacent siblings untouched.
- Note keeps a dedicated one-step atomic undo/redo entry so immediate Ctrl+Z / Ctrl+Y restores/removes the exact same DOM node.
- Any subsequent normal rich-text input invalidates that dedicated atomic history and falls back to the browser's normal undo history.
- No database/schema changes.
