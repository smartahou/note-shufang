# v1.3 · PDF 截图与 Note 关联

## 数据流

1. 书房 PDF 阅读器渲染页面。
2. 用户选择“整页”或“框选”。
3. 浏览器生成 PNG；框选模式先记录归一化坐标，再从 1800px 高清页裁切。
4. 浏览器把 PNG 发回书房本地服务。
5. 书房服务通过 `http://127.0.0.1:3030/api/integrations/shufang/capture` 转交给 Note。
6. Note 使用自身 `multer` 上传逻辑保存图片，并通过原 `writeNotes()` 事务链写入笔记。
7. 笔记正文中的 `figure.note-book-capture` 保存 SHA-256、页码、框选区域等来源元数据。
8. 点击来源链接后，书房以 SHA-256 找到当前书库中的文件并使用 `?page=` 深链定位；`?crop=` 用于短暂标示框选区域。

## 关键约束

- 书房不直接写 `notes.json`。
- 不新增第二份笔记数据库。
- 不以绝对路径作为书籍主身份。
- 不改变 `.shufang/library.db` schema。
- 不改变 v1.2 的笔记清污/隔离策略。
- PNG 最大桥接体积 32 MB。

## 服务发现

书房启动后会把当前 PID、端口、书库根目录写入 `~/.shufang/server.json`。Note 在富文本编辑视图点击来源链接时读取该状态并重定向到当前书房端口；HTML/预览中的来源链接同时保留截图时的书房地址作为静态回退。
